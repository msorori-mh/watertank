# استكمال إشعارات عروض السائق

الحالة بتاريخ 2026-09-15: لا يوجد في المستودع google-services.json أو ربط @capacitor/push-notifications أو مخزن رموز الأجهزة. إشعارات جدول notifications الحالية لا تثبت وجود إشعارات هاتف بالخلفية. لا تفعّل الإسناد العام بهذه الحالة.

## الإعداد المطلوب من مالك مشروع Google / أحمد

1. افتح https://console.firebase.google.com/ بالحساب المسؤول عن المشروع. إذا كان مشروع Google Cloud المستخدم لتسجيل الدخول هو المشروع المعتمد للتطبيق، أضف Firebase إليه بدل إنشاء مشروع آخر دون داعٍ.
2. أضف تطبيق Android باسم الحزمة **app.wayetmaa.mobile** كما يظهر في android/app/build.gradle. لا تغيّر اسم حزمة التطبيق المنشور.
3. نزّل **google-services.json** الخاص بهذا التطبيق. هذا ملف إعداد العميل ذو معرفات غير سرية؛ ضعه في android/app/google-services.json أو أرفقه لهذه المحادثة لاستكمال الربط. لا تستخدم ملف حساب الخدمة مكانه.
4. جهّز تفويض إرسال FCM HTTP v1 للخادم بصلاحيات محدودة للمشروع. تحفظ بيانات اعتماد حساب الخدمة في أسرار بيئة الخادم فقط؛ لا ترسل المفتاح الخاص في المحادثة ولا تحفظه في GitHub أو أصول Android.

## التنفيذ المتبقي بعد تحديد مشروع Firebase

- تثبيت إصدار متوافق مع Capacitor 8 من إضافة Push Notifications ومزامنة bun.lock والإعدادات الأصلية.
- طلب إذن الإشعارات وإنشاء قناة Android لعروض الطلبات، ثم تسجيل token للمستخدم الموثق. دعم تبديل الحساب وتسجيل الخروج وتدوير الرموز وحذف الرموز غير الصالحة.
- حفظ رموز الأجهزة في مخزن خاص وإضافة صندوق إرسال للعروض بصلاحيات خادم فقط. يعالج انتهاء العرض وإعادة المحاولة دون منح الجهاز صلاحية إرسال إشعارات.
- إرسال notification + data بمعرف العرض فقط؛ دون الهاتف أو العنوان التفصيلي على شاشة القفل. اضبط TTL بما لا يتجاوز وقت انتهاء العرض، وراجع حالته من الخادم عند فتحه؛ الإشعار المتأخر لا يسمح بالقبول.
- لا تمدد مهلة العرض لمجرد نجاح طلب FCM؛ قبول FCM للرسالة لا يثبت وصولها للهاتف.
- اختبار هاتفين: الشاشة مفتوحة ومغلقة، الخلفية، رفض الإذن، انقطاع الشبكة وعودتها، تبديل المستخدم، عرض منتهي، وإلغاء الطلب أثناء فتح الإشعار.
- تحديث سياسة الخصوصية وData Safety بحسب التنفيذ الفعلي قبل إصدار Google Play.

هذه خطة ربط وليست ادعاء بتنفيذ push. ملف العامل المجدول المرشح منفصل: db/dispatch_worker_install_candidate.sql، ويُثبت معطلًا بعد توفر pg_cron. الإضافة متاحة على مشروع Lovable بإصدار 1.6.4 لكنها غير مثبتة وقت القراءة. لم تُثبت ولم يُطبّق SQL إنتاجي في هذه الجولة.
